## 4. 最新提交到底已经完成什么

### 4.1 随机性已经进入决策内部

最新规范包含四个宏观状态和五个行业余项；九维独立正负创新形成512个后继分支。`model/stochastic_equilibrium.py` 中的政策近似与残差系统用同一转移、同一概率核生成未来现货的条件均值和方差；`model/full_conditions.py` 再从原始条件独立枚举后继。

它不是把随机数叠加到确定性价格曲线上。程序可以通过完全确定的枚举算法求条件期望，经济环境仍然是随机的。反之，测量误差或随机画图本身不构成主体所面对的结构性不确定性。

代码定位：[随机政策模块](https://github.com/richardssheik107-hub/DSGE-LC/blob/4c28915abf32a493ea11ddd262f3a30f57c458c6/model/stochastic_equilibrium.py)、[完整条件评估器](https://github.com/richardssheik107-hub/DSGE-LC/blob/4c28915abf32a493ea11ddd262f3a30f57c458c6/model/full_conditions.py)。

### 4.2 产业机制已经比较完整

值得保留的结构有：总产量Q、上期产量记忆、有效产能约束、成熟能力、建设队列、爬坡队列、新开工J、在建拥挤成本、库存损耗与非负库存、当期灵活耗用和下一期采购承诺的时点区分。L=1、R=0及其组合也有边界接口。

方法层面值得迁移的是原始条件残差重算、KKT检查、后继可行域检查、冻结政策复验、失败路径保留和配对随机响应。经济方程必须随着所有者SDF和预算重新推导，不能只更换函数名。

### 4.4 当前金融效应不具备足够数值分辨率

最新合成GIRF中，需求和成本创新的对数载荷均为0.00025，直接乘数为exp(0.00025)，约增加0.025003%。这不是1%的需求/成本变动。

锚点第0月，需求冲击使P上升约1.8130e-4，F上升约1.6808e-4；成本冲击使P上升约5.3017e-6。Q当期为0响应，是该合成容量受限区域下的结果，不是一般定理。新开工与后续能力的延迟响应符合模型时点。

但风险溢价的响应远小于价格响应。例如，成本冲击锚点第0月，直接计算 `E[P']−F` 的变化约−1.41e-13，按原E27风险补偿右侧计算约+1.65e-13，连符号都不一致。部分需求起点也存在误差与信号同量级的情形。因此不能据当前图解释金融风险渠道的方向、经济显著性或主导地位。

这项限制由已发布[最新GIRF报告](https://github.com/richardssheik107-hub/DSGE-LC/blob/4c28915abf32a493ea11ddd262f3a30f57c458c6/docs/18_stochastic_girf.md)和CSV直接支持。第0月蒙特卡洛误差为零，只说明当期分支已枚举，不说明政策近似误差、差分消减或方程残差为零。

## 5. 为什么仍未成为完整 DSGE

| 待闭合处 | 最新PE的处理 | 完整DSGE需要的改变 |
|---|---|---|
| 消费与储蓄 | 无完整家庭预算和消费Euler | 明确消费主体、劳动、资产、利润所有权与跨期预算 |
| 下游需求 | 外生规模的净收益/需求曲线 | 最终品生产、要素支付和消费需求共同决定LC耗用 |
| 贴现 | 外部当前b及其路径积 | 企业使用所有者边际价值产生的SDF，保留与未来收益的协方差 |
| 真实资源 | LC物量清算 | 加入最终品与劳动清算，预算相加验证中间支付相消 |
| 风险资本 | 每期外部给定、滚动进入退出 | 明确财富结转、消费、债务/抵押、参与和注资约束 |
| 期货定价 | 三类均值—方差FOC导出E27 | 在新的资产参与结构下重推FOC与清算，不能再独立硬加E27 |
| 宏观变量 | 景气、汇率、利率和风险压力外生 | 区分内生总量/价格、原始随机驱动及开放经济外部条件 |
| 状态 | 不跟踪退出者旧财富 | 新预算下要包含债券、未结算头寸/报价或等价净财富状态 |

所以，老师关于“没有体现shock”的疑问，应落实为“冲击来源、进入条件、响应和识别证据是否充分呈现”。从最新仓库事实看，S并非空白；向DSGE推进的主要新增工作是GE与金融预算闭合。组内稿提供主体组织与研究路线，具体迁移和需要修正的原式见[组内文献对齐](02_group_paper_alignment.md)。

## 6. 新主线的工程取舍

新主线不继续维护两套互相冲突的“现行规范”。根 `project.json` 和 `model/dsge_specification.json` 仅定义新的设计状态；所有旧规范保留在单一归档根。原检查器在自己的快照内运行，新检查器不递归执行历史测试。

快照里的脚本若今后执行 `git rev-parse HEAD`，取得的是执行时新仓库提交，而不是历史源提交。来源应同时记录 `source_commit` 和运行提交，不能修改冻结代码掩盖差异。

这次完成的是有证据的整理和可执行的建模设计，不是把旧模型更名后宣布完整DSGE完成。下一步是先落实[蓝图中的预算、生产与资产参与](03_dsge_blueprint.md)，再按[分阶段门槛](04_implementation_plan.md)编写新的求解器。
