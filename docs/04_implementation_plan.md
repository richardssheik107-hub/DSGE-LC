# 04｜DSGE实施顺序、代码迁移与完成标准

研究方向已确定为完整DSGE。以下顺序让每一步形成可审查的结果，而不把设计文件、条件评估器、随机解和实证论文混为一件事。组内稿仍提供主体与实证章节的组织顺序；经济规范以[统一蓝图](03_dsge_blueprint.md)为准。

## 1. 本轮完成和没有完成的工作

本轮完成仓库梳理、单一目录归档、最新PE工程审计、组内稿逐页模块映射、具体GE预算和市场结构设计，以及后续验收方案。归档文件逐字节保全；最新PE在搬移后通过原四项轻量检查。

本轮没有实现新的GE求解器，没有得到新稳态、GE冲击响应或新后验，也没有重新运行旧完整投影/GIRF。因此根目录状态保持 `DESIGN_AND_CLOSURE_REVIEW`，不能把下面的计划写成已完成实验。

## 2. 建设阶段与退出条件

| 阶段 | 具体交付 | 通过条件 | 不能提前做的声明 |
|---|---|---|---|
| A：主体与会计 | 四类预算、所有权/参与、最终品组合、LC与资产清算、单位字典 | 逐主体账户完整，预算相加推出资源恒等式；没有免费进口、免费资本和重复中间支付 | 不能因为写了26模块就说已求解 |
| B：完整条件实现 | 原始目标、全部FOC/KKT与包络、状态推进、约束表 | 独立条件计数、Walras冗余、导数及各类边界明确；错误政策能被拒绝 | 不能继承旧7+L+R未知量或旧17维坐标 |
| C：确定性锚 | 一套标明合成的参数、初始财富分配、确定性稳态 | 正消费/偿付、所有预算和互补条件同时通过；记录多解/财富分配问题 | 零创新下选取h=0只是一种退化选择，不是唯一持仓证明 |
| D：完整随机均衡 | 同一政策生成消费、价格、SDF、未来利润与影子值 | 独立原条件残差、后继可行域、固定点更新、不同初值/精度比较通过 | 不能把单个市场子块、一个均值路径或仅有IRF程序称为均衡解 |
| E：风险机制 | 需求/成本/抵押约束的状态条件GIRF与风险溢价分解 | 金融信号超过误差；说明约束是否绑定及边际定价者；机制反事实重新求解 | 不能事先宣称风险资本一定显著或期货一定领先现货 |

| G：观测、识别与估计 | 月度观测方程、参数识别、合成恢复、许可合规的真实估计 | 参数与冲击有区分信息，恢复实验和后验诊断通过 | 运行MCMC不等于识别；旧后验和预测成绩不继承 |
| H：论文与混频扩展 | 以组内稿结构组织的新论文、稳健性、必要时混频 | 文字、公式、代码、数据和图表来自同一版本 | 不能把行选择矩阵称作完整混频模型 |

这些是工作包，不是未经核实的工期承诺。A—D中出现经济不闭合时先修方程，不用更强优化器掩盖矛盾。

## 3. 新代码的建议模块

真正开始实现时，新命名空间建议为 `model/dsge/`，不要直接导入归档的 `model` 包。下表是拟建文件，不是当前已经存在的代码。

| 拟建模块 | 职责 | 可借鉴的最新PE经验 |
|---|---|---|
| `parameters.py`、`units.py` | 参数约束、主体与数量单位 | 原配置的明确合成标签；参数不从旧后验自动填充 |
| `state.py`、`transition.py` | 财富/未结算合约、建设爬坡、库存及承诺推进 | 队列时点、L/R边界；新增资产和财务状态另推 |
| `accounts.py` | 四份预算、LC物量、劳动、最终资源与资产清算 | 原物量清算；新增总资源账 |
| `households.py` | 消费效用、M^j、劳动和债券KKT | 新建，旧b不是家庭SDF |
| `production.py`、`downstream.py` | LC生产/开工及下游实际产出和采购 | 旧成本形状与拥挤包络；需求曲线必须改为新技术FOC |
| `storage.py`、`financial.py` | 库存KKT、财富、头寸和抵押条件 | 互补边界与原始残差思想；不复制旧MV闭式定价 |
| `residuals.py` | 对任意政策从原始条件审计 | 旧完整评估器的独立核验结构，不复用其经济残差定义 |
| `steady_state.py`、`solver.py` | 确定性锚、随机政策固定点 | 旧冻结/续算机制、检查点与精度报告 |
| `simulation.py`、`girf.py` | 状态条件响应与机制比较 | 共同随机数、首期分支枚举、失败路径保留 |
| `measurement.py`、`identification.py` | 观测聚合与参数恢复 | 仅迁移统计工具并重新检验，不继承早期半结构状态矩阵 |

迁移每个模块时登记：源提交、借鉴算法、改动的经济假设、对应G模块、有效域和新验收。原归档字节保持不动。

## 4. 哪些旧部分不能直接复制

### 4.1 条件市场内层

旧 `conditional_market.py` 给定Q与外部条件矩求P/F/I/C，并依赖旧常弹性采购及E27。新家庭财富、下游收入、SDF和抵押乘子都与价格同时变化，这个单调内层的条件不再自动成立。它可作PE退化对照，不是新GE求解器的现成内层。

### 4.2 多项式政策和精确矩

旧有限非零风险投影和512分支原始核验可借鉴。但 $M^j=(c'^j/c^j)^{-\gamma_j}$ 与价格的乘积一般不再是旧形式多项式；不能因为P的矩有闭式，就认为 $E[M^jP']$ 或 $E[M^jW']$ 仍有同样闭式。新求积需对完整非线性被积函数逐项验证。

### 4.3 状态推进和影子值

保留旧建设队列索引，不采用相反的“已建年龄”编号后仍沿用旧包络。新增所有者财富改变政策，资本和库存续期项使用所有者M；如果以后加入实物抵押，影子值还要包含约束服务。

### 4.4 原实验图和既有参数

原图是归一化的局部合成PE。新金融财富和消费尺度变化会改变绝对风险承受，不能复制旧a值后声称保持相同金融机制。旧冲击0.00025的量级也不能未经数据支持直接称为行业一标准差。

## 5. 先做怎样的确定性锚

首先固定同一beta及明确初始资产分配，设置所有创新为零，解决全部原始预算、生产和市场条件。I/D/F消费与其自身经营收入、债券收入相容，而不是各自任意给一个正消费后反推无来源的转移。

需特别注意三个退化问题：

1. **无便利服务时的库存。** 在平稳确定性环境、$\alpha_I\le1$、$\beta_I<1$、真实仓储成本边际非负时，正库存内点通常不成立：$P+g'(I)-\alpha_I\beta_IP>0$。因此首个锚很可能是零库存边界。不能复用旧含便利服务的正库存锚，更不能强制所有后续随机状态库存也为零。若研究需要正稳态库存，应先建真实服务机制。
2. **零风险的期货头寸。** 当未来P确定，净支付为零时满足清算的持仓可能不唯一。采用h=0作计算选择要明确注明；风险为正后重新解头寸，不把零风险分配当识别结果。
3. **财富与主体存续。** F没有外部收入重置，其正确定性消费需要可持续的正初始安全资产，对应其他主体的负债。D在本候选中拥有固定经营要素，从其租金取得经营收入；该份额、初始资产与借款下界仍需支持正消费和长期存续。若移除该固定要素并保留可变投入的规模报酬不变技术，内点确定性下D营业利润会为零，需要重新核对其收入来源。不能为构造正消费而凭空补净值。

完成锚后，可识别实物子系统在固定约束区域的一阶局部模型可用于核对时点、符号和局部确定性。零风险全金融系统的持仓FOC退化，不能要求其Jacobian自动满秩或直接作BK判断；完整金融求解从有限正风险锚/延续或明确的高阶选择开始。含库存切换、抵押和风险定价的完整结果仍需要非线性/分段方法。

## 6. 随机求解优先顺序

先用有界低维创新，做小域、少队列的完整系统，例如L=1、R=0；通过后扩展到实际队列。这个退化模型必须仍有四份预算、最终资源和资产清算，不能为了减维退回外给SDF/价格矩的PE。

先验证固定约束区域，再让库存、产能和抵押约束切换。增加冲击规模或状态范围时重新检查后继域。每一步都保存实际配置、源代码版本、政策、求积核、残差分布、尾项诊断、随机种子及失败样本。

针对风险溢价，可并行比较高阶扰动与固定非零风险投影，但选择依据是目标精度与约束处理。SGU04的标准扰动阶数不等于旧投影的多项式次数；二阶结果也不必然足以识别抵押压力的时变溢价效应。新市场定价式必须独立重算，而不是只看优化器loss。

## 7. 必做的机制比较

至少比较完整系统与以下显式模型变体：关闭期货市场（各h=0）、放松F抵押约束、改变初始金融财富但有对应资产对手方、关闭或缩短建设爬坡、以及有/无真实库存服务。每个变体都重新推导或删减相关FOC并重新求均衡。

关闭期货不等于令F=P；没有交易的F可以不定义。放松抵押不等于给家庭免费收入。改变初始财富不等于改变总资源。关闭库存服务不等于把旧负成本直接从资源账删除后其他式不变。

不同模型的福利、价格与风险溢价应基于相同单位、同样的冲击定义和可比较的初始信息；必要时区分过渡与各自长期分布。不能把同一冻结政策放进不同制度后称为政策反事实。

## 8. 接下来最优先的具体任务

下一次实现应聚焦A—C：完成消费和经营者参数/单位字典，固定初始财富与借款边界，写四份预算和两本实物账的残差，落实下游排产技术与库存服务选择，再写完整FOC和确定性锚。通过这些审查后，再迁移旧求解器的数值方法。

这一步会直接把组内稿的家庭模块与LC产业模块连起来，也是判断新模型是否真的达到GE的第一份可计算证据。新增更多冲击、提前做混频MCMC或重新包装旧PPT，都不能替代它。
